# My Knowledge OS v0.3.0 Implementation Plan

Date: 2026-07-22
Design: `docs/superpowers/specs/2026-07-22-v0.3-knowledge-ux-design.md`
Strategy: add v2 contracts and modules beside frozen v1 surfaces, then switch the v0.3 CLI and Skill

## Release boundary

v0.3.0 ships the smallest complete safe workflow:

1. schema-v2 and json-v2 contracts;
2. provider-bound PDF preparation with deterministic evidence digests;
3. immutable Source and Knowledge revisions with current pointers;
4. queue/show, feedback/regeneration, and real-TTY final review;
5. Obsidian record projections and drift recovery;
6. concise Codex Skill orchestration.

Conversational final approval and signed host attestations are v0.3.x work. v0.3.0 may display and
collect feedback in conversation, but only a real TTY can create an approval Review event.

## Task 1 — Freeze machine contracts

- Add JSON Schemas under `schemas/v2/` for prepared content, Source response, Knowledge response,
  Review, Review resolution, record projection, and json-v2 envelopes.
- Add Rust DTOs in `mko-core` with `deny_unknown_fields` and exact enum spellings.
- Add positive and negative golden fixtures, including forbidden user judgment and forged domain
  classification fields.
- Preserve every v1 schema and byte-golden test unchanged.

Gate: schema compilation, Rust round-trip, unknown-field rejection, and fixture validation pass.

## Task 2 — Add the v2 repository substrate

- Add schema-v2 KB detection and scaffolding without mutating schema-v1 repositories.
- Add immutable content-addressed revision storage and CAS current pointers.
- Add one repository-wide mutation lock for every v2 writer.
- Add explicit domain assignment (`user` or configured policy), outside semantic LLM output.
- Add derived-artifact policy (`provider` or `local_only`) and evidence-basis provenance.

Gate: concurrent identical writes converge; stale pointer/revision writes fail without mutation.

## Task 3 — Prepare PDF evidence deterministically

- Normalize Unicode, line endings, block ordering, and locator representation before digesting.
- Emit paragraph/region locators where reliable; label page-only locators as `coarse`.
- Warn before a full Drive hydration/hash above the configured threshold.
- Add macOS/Windows byte-identical prepared-content golden verification.

Gate: same PDF and extractor version produce the same canonical bytes and digest on both targets.

## Task 4 — Write Source and Knowledge revisions

- Validate bounded Source and Knowledge responses against the v2 DTOs.
- Bind every revision to Asset fingerprint, prepared bundle ID/digest, and extractor version.
- Enforce high-risk counterargument/open-question rules from Core-owned confirmed domain policy.
- Keep Source facts, LLM analysis, counterarguments, and user judgment separate.
- Add the exact summarize-then-ask-once behavior to Skill tests.

Gate: unsupported facts cannot enter the grounded section; explicit knowledge intent skips only
the question, never review.

## Task 5 — Queue, show, feedback, and TTY review

- Derive queue state from current pointers plus immutable Review events.
- Render one canonical full card and digest for Source/Knowledge targets.
- Persist request-changes feedback against the displayed revision and regenerate a new revision.
- Publish approve/defer/request-changes Review events under the repository mutation lock.
- Reject non-TTY approval, ambiguous input, stale bytes, stale heads, and changed pointers.
- Echo and confirm exact user judgment text without claiming cryptographic authorship.

Gate: end-to-end Source -> Knowledge -> feedback -> diff -> TTY approval passes.

## Task 6 — Obsidian projections and repair

- Generate `views/records/<record-id>.md` with derived review state and canonical links.
- Make Bases query projection records, never immutable revisions directly.
- Update projections after canonical mutations; report repair-needed if regeneration fails.
- Preserve direct edits in `recovery/manual-edits/` and offer conversion to feedback.
- Regenerate only manifest-owned projections; never overwrite user notes or Canvas files.

Gate: approved items enter the Knowledge Library, pending items stay in Review Queue, and drift
recovery loses no user bytes.

## Task 7 — Skill, docs, and release gates

- Keep `SKILL.md` concise and move DTO/recovery details to one-level references.
- Update CLI/Skill compatibility checks to v0.3.0 and json-v2.
- Add clean-machine setup, two-device, hostile-document, and ambiguous-approval forward tests.
- Run format, clippy, workspace tests, independent review, and the manual Drive Stream smoke test.

Gate: all automated checks pass and the live smoke record reports only observed evidence.
