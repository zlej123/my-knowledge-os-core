# My Knowledge OS v0.2 Usability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Personal PDF workflow usable through one-time setup, concise deterministic commands, and one conversational skill while preserving v0.1 records and human-only approval.

**Architecture:** Add a compatibility-preserving UX facade over the existing Rust Core. New profile, import, scan, diagnostics, and review modules own deterministic state; a versioned JSON contract connects them to one Codex skill that owns semantic interpretation only. Existing detailed commands and on-disk contract `0.1.0` remain valid.

**Tech Stack:** Rust 1.97.0, clap 4.6.2, serde/serde_json, cap-std, atomic-write-file, Git, Markdown Codex Skills.

## Global Constraints

- Product executable version becomes `0.2.0`; knowledge contract version remains exactly `0.1.0`.
- Personal Scope and PDF only; Shared, Work, other formats, Drive API, RAG, daemon, GUI, and Obsidian plugin remain out of scope.
- The deterministic Core owns paths, copying, fingerprints, IDs, Registry/Source records, locks, checks, and approval.
- The LLM writes only strict `semantic-response-v1` temporary JSON from the bounded prepared bundle.
- Agents never invoke `mko review`, approve, stage, commit, push, delete originals, or bypass Core errors.
- `provider_root` is the exact `My-Knowledge-OS-Assets/personal/inbox`, never a Drive account root.
- Existing v0.1 `--json` and detailed command behavior remain unchanged; agent calls use `--format json-v1`.
- Use TDD for every task and run `scripts/fmt.sh --check`, `cargo clippy --workspace --all-targets -- -D warnings`, and `cargo test --workspace` before milestone review.
